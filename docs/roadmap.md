# Roadmap

## 1. Введение

Документ определяет:
1. Разделение на эпики по спринтам
2. Определение зависимостей задач
3. Приоритизация MVP функций
4. Определение не-скоупа (что НЕ входит в MVP)
5. Планирование рисков и их митигация

В рамках проекта **БПТА — ИИ-система подготовки к зачёту по конспекту**.

**Цель продукта:** сократить время подготовки студента к зачёту за счёт автоматической генерации учебных карточек из конспекта и организации интервального повторения.

**North Star Metric:** число циклов повторения набора карточек до его полного закрытия правильными ответами (меньшее значение при сопоставимой сложности материала — лучший результат).

**Основной сценарий MVP:** студент загружает конспект (TXT/MD/PDF) и список вопросов по зачёту → система генерирует карточки → студент принимает карточки → проходит сессию повторения с кривой забывания → видит прогресс усвоения.

### Спринт 3 — AI-пайплайн и генерация карточек

**3.a. Эпик: Реализация AI-пайплайна генерации карточек**
- Приём документа (TXT/MD/PDF)
- Извлечение текста (PyMuPDF для PDF)
- Очистка и нормализация текста
- Разбиение на фрагменты до 5 000 символов (chunk_id + source_locator)
- Формирование промпта (system + user prompt с JSON Schema)
- Генерация карточек через Ollama Cloud (gemma4:31b)
- Разбор JSON ответа
- Валидация карточек (тип, поля, цитата, формула, переменные)
- Дедупликация (точное сравнение нормализованных вопросов)
- Сохранение карточек со статусом `pending`

**3.b. Эпик: Деградация и резервные модели**
- Переключение на локальную модель (qwen3.5:4b) при исчерпании квоты облака
- Обработка ошибок HTTP (429, 5xx, timeout)
- Логирование запросов (request_id, job_id, latency_ms, token counts)

**3.c. Эпик: Экран приёмки карточек**
- Отображение карточек (вопрос, ответ, тип, страница, цитата)
- Действия: принять, редактировать, удалить, перегенерировать
- Переход карточки в статус `accepted` и добавление в активную колоду

**Результат спринта:** рабочий AI-пайплайн, экран приёмки, логирование.

**4.b. Эпик: Сессия повторения**
- Формирование очереди карточек на сегодня

- Приём текстового ответа студента

**4.c. Эпик: Оценка свободного ответа**

- Обработка низкой уверенности (`requires_self_check=true`)
- Самооценка студента при спорных случаях
- Запись событий качества (`grade_disputed`)

**Результат спринта:** рабочая сессия повторения, оценка ответов, обновление расписания.

   - Статус `pending` до ручной приёмки

   - Действия: принять, редактировать, удалить, перегенерировать
   - Переход в статус `accepted` и добавление в активную колоду

4. **Сессия повторения с кривой забывания** (UC-04)
   - Формирование очереди карточек на сегодня
   - Приём текстового ответа студента
   - Обновление расписания на основе ответа

5. **Оценка свободного ответа** (UC-05)
   - AI-оценка ответа (correct / partially_correct / incorrect)
   - Обработка низкой уверенности (requires_self_check)
   - Самооценка студента при спорных случаях
   - Запись событий grade_disputed

6. **Просмотр прогресса усвоения** (UC-06)
   - Сводная статистика (карточки, циклы, процент усвоения)
   - Список вопросов с индикацией статуса
   - North Star Metric (число циклов до закрытия)

7. **Деградация и резервные модели**
   - Переключение на локальную модель при исчерпании квоты облака
   - Обработка ошибок HTTP и таймаутов
   - Логирование запросов и токенов

1. **RAG для тематических запросов**
   - Индекс с document_id, chunk_id, текстом, страницей и embedding
   - Поиск релевантных фрагментов по запросу студента
   - Генерация карточек по найденным фрагментам

2. **Мультимодальная обработка**
   - Обработка сканированных PDF (OCR)
   - Распознавание формул как изображений

   - Прогноз времени до закрытия набора
   - Сравнение результатов между студентами

4. **Адаптивный алгоритм повторения**
   - Калибровка параметров кривой забывания по данным пользователя
   - Учёт сложности карточки и времени ответа

5. **Интеграция с внешними системами**
   - Импорт конспектов из LMS (Moodle, Canvas)
   - Экспорт карточек в Anki, Quizlet

6. **Мобильное приложение**
   - Нативное приложение для iOS/Android
   - Оффлайн-режим с локальной моделью
   - Push-уведомления о необходимости повторения

7. **Социальные функции**
   - Общие наборы карточек по курсу

## 5. Не-скоуп (что НЕ входит в MVP)

Следующие функции и требования **явно исключены** из MVP и могут быть рассмотрены в будущих итерациях:

### Исключено из MVP:

1. **Авторизация и регистрация пользователей**
   - MVP предполагает одного пользователя (студента) без системы аккаунтов
   - Аутентификация, роли, управление доступом — после MVP

2. **Многопользовательский режим**
   - MVP не поддерживает одновременную работу нескольких студентов
   - Общие наборы карточек, совместное обучение — после MVP

3. **Обучение собственной LLM**
   - MVP использует готовые модели (Ollama Cloud, локальная Ollama)
   - Fine-tuning, дообучение на данных пользователя — после MVP

4. **Агентный подход в генерации**
   - MVP использует управляемый workflow (код задаёт порядок шагов)
   - Автономный агент с доступом к инструментам — после MVP

5. **RAG для первичной генерации**
   - MVP обрабатывает все фрагменты последовательно (полный проход)
   - RAG добавляется для тематических запросов после MVP

6. **Мультимодальная обработка**
   - MVP работает только с текстовыми PDF, TXT, MD
   - OCR, распознавание формул как изображений, анализ схем — после MVP

7. **Мобильное приложение**
   - MVP — веб-приложение (адаптивная вёрстка для мобильных браузеров)
   - Нативное приложение — после MVP

8. **Интеграция с внешними LMS**
   - MVP не интегрируется с Moodle, Canvas и другими системами
   - Импорт/экспорт — после MVP

9. **Расширенная аналитика и отчёты**
   - MVP включает базовую статистику и North Star Metric
   - Графики, прогнозы, сравнения — после MVP

10. **Пуш-уведомления и напоминания**
    - MVP не отправляет уведомления о необходимости повторения
    - Email/SMS/push — после MVP

11. **Админ-панель**
    - MVP не включает управление пользователями, курсами, моделями
    - Администрирование — после MVP

12. **Коммерческая монетизация**
    - MVP — учебный проект без платных функций
    - Подписки, кредиты, тарифы — после MVP

### Технические ограничения MVP:

1. **Один документ за раз**
   - MVP не поддерживает одновременную обработку нескольких конспектов
   - Очередь документов — после MVP

2. **Ограниченный размер документа**
   - MVP тестируется на документах до 20 страниц
   - Обработка больших документов (сотни страниц) — после MVP

3. **Локальное хранение данных**
   - MVP хранит данные в локальной PostgreSQL
   - Облачная база, резервные копии, шифрование — после MVP

4. **Без гарантий доступности**
   - MVP не обеспечивает SLA, мониторинг, автоматическое восстановление
   - Production-ready инфраструктура — после MVP

5. **Без защиты от adversarial атак**
   - MVP не включает защиту от prompt injection через загруженный документ
   - Безопасность на уровне production — после MVP

## 6. Планирование рисков и их митигация

### Риск 1: Ошибки или задержки при генерации карточек через LLM

**Описание:** модель может вернуть некорректный JSON, фактически неверные карточки или не уложиться в таймаут.

**Митигация:**
- Обязательная валидация JSON и цитат после модели
- Деградация на локальную модель при недоступности облака
- Экран ручной приёмки для контроля качества
- Логирование ошибок и повторные попытки (не более 2)
- Golden dataset для регулярной проверки качества

---

### Риск 2: Исчерпание бесплатной квоты Ollama Cloud

**Описание:** Ollama Cloud не публикует точный размер стартовой квоты; после исчерпания генерация через облако невозможна.

**Митигация:**
- Локальная модель (qwen3.5:4b) как резерв
- Логирование token counts (prompt_eval_count, eval_count)
- Предупреждение пользователя при остатке < 20% квоты
- Возможность ручного создания карточек без LLM

---

### Риск 3: Низкое качество локальной модели

**Описание:** локальная qwen3.5:4b медленнее и менее точна, чем облачная gemma4:31b; возможны ошибки в формулах и нестабильный JSON.

**Митигация:**
- Уменьшение размера контекста и максимального ответа
- Обязательный экран приёмки (пользователь проверяет каждую карточку)
- Возможность перегенерации отдельной карточки
- Сравнение моделей на golden dataset

---

### Риск 4: Смысловые дубли между карточками

**Описание:** модель может создать карточки, проверяющие одно и то же знание разными словами.

**Митигация:**
- Точная дедупликация (нормализация вопросов)
- Семантически похожие пары показываются пользователю (не удаляются автоматически)
- Учёт обозначения результата, страницы и контекста при классификации

---

### Риск 5: Низкая вовлечённость студентов в повторение

**Описание:** студенты могут не возвращаться к системе для регулярного повторения, что снизит эффективность интервального обучения.

**Митигация:**
- Отображение прогресса и North Star Metric (мотивация через визуализацию)
- Уведомления о карточках, требующих повторения (после MVP)
- Геймификация и достижения (после MVP)
- Минимизация времени сессии (карточки выдаются в оптимальном порядке)

---

### Риск 6: Проблемы с производительностью при обработке больших документов

**Описание:** обработка PDF из 8 страниц занимает ~20 секунд (облако) или ~7 минут (локально); большие документы могут вызывать таймауты.

**Митигация:**
- Разбиение на фрагменты до 5 000 символов
- Последовательная обработка фрагментов (очередь)
- Индикатор прогресса в интерфейсе
- Возможность прервать задание и сохранить частичный результат

---

### Риск 7: Нестабильность JSON-контракта

**Описание:** Ollama Cloud не поддерживает принудительный JSON Schema; модель может вернуть Markdown-обёртку или дополнительные пояснения.

**Митигация:**
- Строгий json.loads с обработкой ошибок
- Снятие Markdown-ограды (```json ... ```)
- Локальная проверка схемы и типов полей
- Один ограниченный повтор при невалидном JSON
- Логирование ошибок контракта

---

### Риск 8: Фактические ошибки в карточках

**Описание:** модель может создать карточку, где ответ не подтверждается источником или содержит внешние факты.

**Митигация:**
- Обязательная точная цитата из источника (source_fragment)
- Программная проверка наличия цитаты в исходном фрагменте
- Различение factual_error и invalid_source_fragment
- Исправление только цитаты (не всей карточки) при ошибке оформления
- Ручная приёмка перед добавлением в колоду

---

### Риск 9: Проблемы с инфраструктурой и запуском

**Описание:** Compose-стек может не запуститься из-за ошибок конфигурации, сетей или health checks.

**Митигация:**
- Smoke-тест чистого запуска (scripts/check-compose.py)
- Раздельные сети (frontend, backend, ai) для изоляции
- Health checks для всех сервисов
- Документация воспроизведения (delivery-report)

---

### Риск 10: Расхождение имён артефактов и автопроверка

**Описание:** бот автопроверки требует точного соответствия имён файлов, заголовков UC и элементов диаграммы.

**Митигация:**
- Единый шаблон имён (UC-01-<name>.md)
- Дословное совпадение названий UC в .puml и .md
- Чек-лист перед коммитом (проверка структуры, имён, наличия .svg)
- CONTRIBUTING.md с правилами работы с репозиторием
