# UC-05. Оценка свободного ответа студента

**Актёр:** Система (ИИ-агент), Студент (косвенно)
**Цель:** автоматически оценить текстовый ответ студента на карточку по смысловому соответствию эталону и выявить фактические ошибки
**Предусловия:** студент ввёл текстовый ответ на карточку в процессе сессии повторения (UC-04); карточка имеет статус `accepted` и содержит вопрос, эталонный ответ, точную цитату и 1–4 обязательных смысловых пункта
**Триггер:** студент нажимает кнопку «Проверить ответ»

## Основной сценарий
1. Система формирует запрос к ИИ-модели, включая: вопрос, эталонный ответ, точную цитату из источника, обязательные смысловые пункты и текстовый ответ студента.
2. Система отправляет запрос в облачную модель (`gemma4:31b`) или локальную (`qwen3.5:4b`).
3. Модель возвращает JSON с оценкой (`correct`, `partially_correct`, `incorrect`), списком найденных пунктов, пропусков, фактических ошибок и уровнем уверенности (`confidence`).
4. Система проверяет JSON на соответствие схеме и допустимые статусы оценки.
5. Если уверенность модели высокая, система сохраняет оценку и обновляет расписание повторения карточки.
6. Система возвращает студенту результат проверки, объяснение и эталонный ответ для ознакомления.

## Альтернативы и исключения
- **4а. Модель вернула некорректный JSON.** Система выполняет один ограниченный повтор запроса. Если повтор тоже невалиден, система переходит к сценарию 6б (низкая уверенность/ошибка).
- **5а. Уверенность модели низкая (`requires_self_check=true`).** Система не считает решение окончательным. Она показывает студенту эталонный ответ и объяснение модели, но просит студента самостоятельно подтвердить или оспорить оценку. Расписание обновляется на основе выбора студента.
- **5б. Студент оспаривает оценку.** Студент нажимает «Оспорить». Система фиксирует статус `grade_disputed`, сохраняет ответ студента и оценку модели в eval-набор для последующего анализа и улучшения промптов.

## Негативные сценарии (error handling)
- **2а. Ошибка сети или тайм-аут при запросе к модели.** Система повторяет запрос с экспоненциальной задержкой (не более двух попыток). Если все попытки исчерпаны, система сообщает о проблеме и просит студента оценить ответ самостоятельно (как в 5а).
- **2б. Ошибка авторизации (401/403) или исчерпание квоты.** Система переключается на резервную локальную модель. Если локальная модель также недоступна, запрос прерывается, и студенту предлагается оценить ответ самостоятельно.

## Конечное состояние
- При успешном сценарии или альтернативных сценариях 4а/5а/5б — оценка сохранена, расписание карточки обновлено, студент ознакомлен с результатом.
- При негативных сценариях — оценка не сохранена, карточка остаётся в очереди на проверку, студент может повторить попытку или оценить ответ вручную.

## Результат
Текстовый ответ студента оценён, обратная связь предоставлена, расписание интервального повторения скорректировано. Спорные случаи сохранены для дообучения системы.

## Как поймём, что работает
- Модель возвращает валидный JSON со статусом `correct`, `partially_correct` или `incorrect` в 95% случаев.
- Время оценки одного ответа не превышает 2–3 секунд.
- Студент видит понятное объяснение, какие смысловые пункты он упустил или исказил.
- Все случаи `grade_disputed` корректно логируются и попадают в eval-набор без потери данных.
