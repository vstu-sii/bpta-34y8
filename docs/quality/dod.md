## Приёмка качества продукта после реализации (лаба 3)

- Q1 grounded ≥ 90%, Q2 useful ≥ 80%, Q4 duplicates ≤ 10%, Q5 coverage ≥ 90% —
  предварительные пороги из лабы 1; подтвердить в review до первого прогона.
- Q3 exact accuracy ≥ 85% на трёх метках `correct / partially_correct / incorrect`;
  показать 3×3 confusion matrix и число ложных `correct` (цель 0).
- Неподтверждённая цитата, критическая фактическая ошибка, чужие данные,
  исполнение вывода как кода и утечка секрета блокируют приёмку независимо от процентов.
- Пустой результат по ответимому кейсу считается пропуском покрытия; ошибка/таймаут
  не исключается из знаменателя. Нет результатов — «не измерено», а не PASS.
- Подтверждение структуры JSON и дословной цитаты не доказывает смысловую верность.
- До запуска фиксируются SHA, версия набора/промпта/модели, параметры и среда.
  Порог задержки/стоимости согласуется отдельно после baseline; их нельзя выдумывать.
