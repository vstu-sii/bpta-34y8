# Критерии успеха проекта

## Проект

Система для создания карточек повторения на основе конспекта студента.

Пользователь загружает или передаёт конспект, после чего система
выделяет материал, который имеет смысл повторять, и создаёт карточки
с вопросами и эталонными ответами.

Пользователь отвечает на вопросы свободным текстом.
Система оценивает ответ и в дальнейшем может использовать результаты
для организации повторений.

> Целевые значения метрик являются предварительными
> и должны быть согласованы с Product.

---

## 1. Корректность карточек

### Критерий

Информация в созданной карточке должна соответствовать исходному
конспекту и не содержать выдуманных фактов.

### Метрика

Доля корректных карточек:

корректные карточки / все проверенные карточки × 100 %

### Предварительное целевое значение

Не менее 90 % карточек должны быть подтверждены исходным конспектом.

### Способ проверки

Карточки проверяются на тестовом наборе примеров.
Для каждой карточки сравниваются вопрос и эталонный ответ
с исходным фрагментом конспекта.

---

## 2. Полезность карточек

### Критерий

Карточка должна проверять информацию, которая действительно содержится
в конспекте и имеет смысл для повторения.

### Метрика

Доля полезных карточек:

полезные карточки / все созданные карточки × 100 %

### Предварительное целевое значение

Не менее 80 % созданных карточек должны быть признаны полезными
для повторения.

### Способ проверки

Карточки оцениваются человеком по критерию:
«Имеет ли смысл повторять эту информацию при подготовке по конспекту?»

---

## 3. Корректность оценки ответа пользователя

### Критерий

Система должна правильно определять, соответствует ли свободный ответ
пользователя эталонному ответу.

### Метрика

Accuracy:

правильно оценённые ответы / все проверенные ответы × 100 %

### Предварительное целевое значение

Не менее 85 % ответов должны оцениваться так же,
как их оценил человек.

### Способ проверки

Для набора тестовых вопросов заранее создаются ответы пользователей
и человеческая оценка результата.

Оценка системы сравнивается с эталонной оценкой.

---

## 4. Отсутствие повторяющихся карточек

### Критерий

Система не должна создавать несколько карточек,
проверяющих один и тот же факт практически одинаковым способом.

### Метрика

Доля дубликатов:

количество дублирующихся карточек / общее количество карточек × 100 %

### Предварительное целевое значение

Не более 10 % карточек могут быть дубликатами.

### Способ проверки

Карточки из тестового набора проверяются на смысловые повторы.

---

## 5. Время ответа системы

### Критерий

Пользователь не должен слишком долго ждать результата обработки запроса.

### Метрика

Время от отправки запроса до получения ответа системы.

### Предварительное целевое значение

Не более 10 секунд для обычного запроса.

Дополнительно в дальнейшем может измеряться p95 latency.

### Способ проверки

Время выполнения запроса автоматически фиксируется приложением
во время тестирования.

---

## 6. Стоимость обращения к модели

### Критерий

Использование модели не должно приводить к неоправданно высокой
стоимости работы системы.

### Метрика

Средняя стоимость одного запроса:

общая стоимость запросов / количество запросов.

### Предварительное целевое значение

Конкретное значение будет определено после выбора модели
и согласовано с командой.

### Способ проверки

Количество использованных токенов и стоимость запросов
фиксируются во время тестирования.

---

# Автоматические метрики

В следующих лабораторных работах планируется автоматически собирать:

- время обработки запроса;
- количество успешных и ошибочных запросов;
- количество используемых токенов;
- стоимость запросов к модели;
- результаты проверки системы на golden dataset.
