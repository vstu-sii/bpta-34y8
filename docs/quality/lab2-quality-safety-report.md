## 4. Definition of Done

В DoD у каждого артефакта команды есть проверяемый результат и доказательство:
UC, проживание, roadmap, glossary, AI pipeline, выбор модели, spike, API,
C4, aact, ADR, UI, схема/миграции, Compose и документы качества.
Критерии основаны на наличии, числе, команде проверки или ссылке на review.
Решения по цене модели не смешиваются с архитектурными ADR.

Отдельно заданы будущие критерии продукта: grounded/useful/coverage, оценка
свободного ответа, критические дефекты, цитаты и права владельца. Пороговые
значения из предыдущей лабы оставлены предложениями для review, а не выданы за
утверждённые командой. Старый p95 ≤ 10 с не перенесён как обязательный gate:
PRD и AI-пайплайн требуют baseline на согласованном размере контекста.

## 5. Golden dataset v1

### 5.1. Объём и состав

| Задача | Количество | Назначение |
|---|---:|---|
| Generate | 16 | Grounded карточки, определения, процессы, сравнения, формулы, шум и инструкции в данных |
| Abstain | 4 | Нет ответа, противоречивый источник, инструкция без учебного содержания |
| Evaluate | 20 | Перефразы, частичный ответ, неправильный ответ и инъекция в ответе |
| **Всего** | **40** | Объём соответствует требованию 30–50 пар |

Среди ответов студента: 10 `correct`, 5 `partially_correct`, 5 `incorrect`.
Бинарная проекция: 10 accepted против 10 rejected. Есть четыре формульных кейса
и восемь кейсов с инструкциями/markup в недоверенных данных.

### 5.2. Контекст и эталон

Каждый пример содержит уникальный ID, версию, QS-UC, происхождение, исходный
текст и вопрос, ожидаемое действие, эталон и пояснение. Контекст включает chunk,
locator и страницу. Для карточки проверяется точная цитата в правильном контексте;
для формулы — точное выражение и обозначения; смысловой grounded требует review.
Оценка ответов использует существенные смысловые пункты и метки текущего API.
Проверка цитаты не заменяет проверку того, что она подтверждает ответ.

В текущем внутреннем AI API нет поля экзаменационного вопроса: это отмечено как
вопрос продуктового адаптера. Набор не маскирует этот пробел добавлением вопроса
в текст доказательного источника. `abstain` — ожидаемое поведение продуктового
workflow, а не несуществующий статус AI API.

### 5.3. Источники и воспроизводимость

Все тексты синтетические и оригинальные, без личных данных и заимствованных
учебных документов. Независимая двойная разметка и реальные интервью не заявляются.
SHA-256 набора:

```text
2b6ce4aeb5ebbef774a503a23b61ffed33bddd3488606d6fba7f23770fc734a7
```

Checksum хранится в `manifest.json`. `.gitattributes` фиксирует LF для JSONL,
чтобы Git checkout Windows/Linux не менял frozen набор. Новые случаи/изменение
эталона проходят PR и новую версию. Набор мал и синтетический: это стартовый
контрольный набор, а не доказательство статистически устойчивого качества на
реальных пользователях. Для пилота запланировано ≥ 10 реальных разрешённых случаев.

## 6. Инструмент проверки и CI

Файлы: `tools/quality/evaluate.py`, `test_evaluate.py`, `requirements.txt`,
`.github/workflows/quality.yml`.

`validate` проверяет JSON Schema, checksum, уникальность ID и входов, объём,
баланс меток, покрытие пяти сценариев, цитаты, формулы, source mapping,
соответствие карточек и запросов оценки текущему OpenAPI.

`score` читает записанные реальные предсказания, требует все 40 ID, подсчитывает
числители/знаменатели метрик, confusion matrix, ложные correct и ошибки.
Для каждой сгенерированной карточки необходим semantic review человека.
При пропуске результата, невалидном формате, критической ошибке, нарушении
контекста или недостигнутом gate возвращается ненулевой код. Ошибки модели
остаются в знаменателе. Инструмент не вызывает модель и не расходует API-токены.

Регрессионные тесты проверяют корректный подсчёт на искусственном harness,
дубликат и отсутствие ID, ложное correct при accuracy 95%, таймаут, выдуманную
цитату, чужой locator, критическую ошибку, отсутствие review, пустую генерацию
и карточку по неответимому вопросу. Искусственные harness-ответы не сохранены
как результаты модели и не используются для заявления о качестве продукта.

CI на PR устанавливает зафиксированные зависимости, валидирует набор, запускает
11 тестов и публикует JSON проверки. Реальные интеграционные тесты и облачные
evals описаны для лабы 3; в текущем workflow они не имитируются.

## 7. Модель угроз и тест-план

Модель угроз использует [OWASP LLM Top 10 2025](https://genai.owasp.org/llm-top-10/),
проверенный при подготовке. В документе приведена собственная оценка применимости
всех десяти категорий к проекту: меры, владельцы и критерии атак.
Векторный поиск пока отсутствует — риск рассмотрен условно и требует пересмотра
при добавлении RAG. Для каждой точки входа указано, что может сделать обманутая
модель. Запрет доступа к БД/инструментам должен обеспечиваться реализацией,
а не только текстом prompt. Отдельно отмечена общая backend-сеть app и agent.

В тест-плане определены unit, интеграционные, eval, security и UX-проверки;
среды, владельцы, команды, будущий запуск в CI, правила baseline latency/cost,
стоп-критерии и состав отчёта. Атаки лабы 4 перечислены как NOT RUN.
Применимость требований к реальным персональным данным должна быть определена
до их использования; юридическая оценка в эту синтетическую проверку не входила.

## 9. Найденные межролевые вопросы

| ID | Наблюдение | Действие / владелец |
|---|---|---|
| QS-OPEN-01 | Нет согласованных UC и протокола проживаемости | Product: опубликовать UC, сопоставить QS-UC, провести проживание |
| QS-OPEN-02 | ADR имеют статус proposed, приёмка не зафиксирована | Product + Delivery: review и решение |
| QS-OPEN-03 | API лежит в `docs/api/`, задание указывает `api/` | AI + Delivery: выбрать канонический путь, обновить ссылки |
| QS-OPEN-04 | OpenAPI server `ai-service:8000`, Compose использует `agent:8001` | AI + Delivery: согласовать адрес |
| QS-OPEN-05 | В SQL нет типов карточек, formula/variables; `partial` отличается от `partially_correct`; chunk_id UUID vs integer | AI + Delivery: схема и явный mapping |
| QS-OPEN-06 | Внутренний AI request не передаёт exam_question | Product + AI: контракт продуктового workflow и адаптер evals |
| QS-OPEN-07 | Порог скорости старого DoD расходится с PRD и условиями AI-прогона | Команда: baseline на едином входе, затем порог |
| QS-OPEN-08 | Локальный Compose не подтверждён: нет POSTGRES_PASSWORD в `.env`, Docker Engine недоступен при предыдущей проверке | Delivery: безопасно настроить среду и запустить smoke |
| QS-OPEN-09 | Независимое review эталонов/DoD/test-plan ещё не выполнено | Product + AI + Delivery: зафиксировать замечания/принятие в PR |

Эти вопросы не исправлялись скрытыми изменениями чужих артефактов и не объявлены
разрешёнными. Они отделяют готовность комплекта QS от готовности всей команды.

## 10. Команды воспроизведения

Из корня репозитория:

```powershell
python -m pip install -r tools/quality/requirements.txt
python tools/quality/evaluate.py validate --output quality-validation.json
python -m unittest discover -s tools/quality -p 'test_*.py' -v
python -m ruff check tools/quality
python -m ruff format --check tools/quality
```

После реализации и записи реальных ответов адаптера:

```powershell
python tools/quality/evaluate.py score --predictions predictions.jsonl --output evaluation.json
```

Последняя команда не запускалась на реальной модели: соответствующих входных
результатов сейчас нет. Рубрика/формат описаны в README набора.
