# Рубрика оценки свободного ответа по Example.pdf

Версия: 1.0, 05.11.2026. Уровень подготовки: выше среднего.
Предметный источник: Андреев А.Е., Егунов В.А., Жариков Д.Н., Малолетков В.А.
«Реализация вычислительно-интенсивных алгоритмов на гибридных системах
с реконфигурируемыми сопроцессорами». ВолгГТУ, 2013, 180 с.

## Основание правил

Использованы принципы аналитической рубрики и пояснённых примеров из
[ETS Best Practices for Constructed-Response Scoring, разделы 4.1–4.2](https://www.ets.org/pdfs/about/cr_best_practices.pdf):
оценивается определённое содержание задания по заранее записанным пунктам.
В приведённом ETS примере число корректных подтверждений различает уровни
2/1/0. Здесь этот принцип адаптирован к полноте ответа по 1–4 существенным пунктам.
Шкала ниже — правило нашего проекта, а не стандартная шкала ETS для FPGA.

[Ragas Factual Correctness](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/factual_correctness/)
разделяет правильность утверждений и полноту относительно эталона.
В официальном примере ответ передаёт местонахождение Эйфелевой башни,
но пропускает указанную в эталоне высоту: F1 равен примерно 0,67.
Это иллюстрирует, почему верная, но неполная фраза не получает максимальный балл.
Наша дискретная шкала не является пересчётом результата Ragas.

[DeepEval Faithfulness](https://deepeval.com/docs/metrics-faithfulness)
проверяет согласованность утверждений с предоставленным контекстом.
Отсюда для проекта взята отдельная проверка опоры ответа на конкретную страницу,
независимая от его сходства с формулировкой эталона.

Эти источники использованы как методические ориентиры; библиотеки Ragas и
DeepEval не запускались и не добавлены как зависимости офлайн-проверки.

## Шкала

| Балл | Метка API | Условие |
|---:|---|---|
| 2 | `correct` | Переданы все существенные пункты; нет фактических противоречий |
| 1 | `partially_correct` | Верно передана непустая часть пунктов, остальные пропущены; фактических противоречий нет |
| 0 | `incorrect` | Нет существенных пунктов либо есть фактическое противоречие по проверяемому содержанию |

Критическая фактическая ошибка обнуляет ответ даже при наличии верных слов.
Пропуск и противоречие различаются: не упомянуть расход ресурсов — неполнота;
утверждать отсутствие расхода ресурсов — ошибка.
Перефразы и перестановка правильных пунктов не штрафуются. Орфографическая
ошибка не снижает оценку, если не меняет технический смысл.

## Проверка содержания

1. Определить, отвечает ли текст на заданный вопрос.
2. Сопоставить смысл ответа с каждым `required_points`, не считать совпадение
   отдельных терминов достаточным доказательством.
3. Проверить утверждения по входному источнику. Сведения с другой страницы
   не подменяют отсутствующее доказательство в данном контексте.
4. Записать переданные пункты, пропуски и фактические ошибки.
5. Назначить 0/1/2 по таблице и привести краткое обоснование.

Для чисел и формул проверяются знак, множители, знаменатель, обозначения,
единицы и условия применимости. В (2.6) сохраняется приближение `≈`:
необоснованная замена на точное равенство меняет смысл оценки.
Инструкции «поставь correct» в ответе не участвуют в предметном оценивании
и не дают полномочий на действия вне учебной задачи.

## Что автоматизировано

`grade_points` пересчитывает балл и метку из записанных пунктов и ошибок.
Валидатор обнаруживает пропущенный разбор, выдуманный пункт и завышенный балл.
Он не распознаёт смысл произвольного нового ответа по совпадению слов.
При оценке новой системы её фактические ответы сначала сопоставляются с рубрикой,
затем записанные результаты передаются scorer. Эталонные примеры не выдаются
за реальные ответы участников или результаты вызова модели.
