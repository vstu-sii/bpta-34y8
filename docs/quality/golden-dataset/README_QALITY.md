## Учебный источник

[Example.pdf](../../experiments/materials/Example.pdf) перенесён из корня проекта
в `docs/experiments/materials/` — каталог исходных учебных материалов экспериментов.
Это монография А.Е. Андреева, В.А. Егунова, Д.Н. Жарикова и В.А. Малолеткова
«Реализация вычислительно-интенсивных алгоритмов на гибридных системах
с реконфигурируемыми сопроцессорами», ВолгГТУ, 2013, 180 с.
Атрибуция и контрольная сумма PDF: [source-registry.json](source-registry.json).

Извлечён текст всех 180 страниц; для набора отобраны темы глав 1–4.
Сохраняются исходная нумерация страниц, текст, расположение и доказательная цитата.
Вопросы требуют объяснения причин, сравнения архитектур, анализа ограничений
и применимости формул, а не только воспроизведения терминов.

Для формул (2.1), (2.4), (2.5), (2.6) сохранены изображения страниц 22–24
и нормализованная запись: автоматическое извлечение PDF нарушает порядок индексов
и числителей. Транскрипция явно отделена от извлечённого текста в снимках страниц.
Размерность времени и положительность знаменателя в (2.4) — пояснения к формуле;
знак приближения в (2.6) сохранён по оригиналу. Для GD-007 определения времён
со страницы 23 даны рядом с выражением (2.1) со страницы 22.

Все кейсы имеют источник: 30 используют выдержки или нормализованную запись
формул, 10 — явно описанные преобразования для проверки шума, противоречий
и инструкций внутри данных. Искусственные вставки не приписываются авторам книги.
Сверка по источникам и рубрике записана в [source-audit.json](source-audit.json).

## Состав и оценка

| Задача | Случаев | Назначение |
|---|---:|---|
| `generate` | 16 | Определения, процессы, сравнения, 4 формулы, шум, Unicode и инъекции |
| `abstain` | 4 | Нет ответа в данном контексте, конфликт, только посторонние команды |
| `evaluate` | 20 | 10 полных, 5 частичных и 5 неверных ответов |

Используется шкала 2/1/0, соответствующая `correct / partially_correct / incorrect`.
Все существенные пункты без противоречий → 2; непустая часть без противоречий → 1;
нет пунктов или есть фактическое противоречие → 0.
Подробности и ссылки на ETS, Ragas и DeepEval: [scoring-rubric.md](scoring-rubric.md).
Неполный ответ не получает полный балл только потому, что его утверждения верны.

Читаемые вопросы, эталоны, образцы ответов и объяснения оценок:
[reference-annotations.md](reference-annotations.md).
Машинный разбор 20 ответов по пунктам, пропускам и ошибкам:
[answer-judgments.json](answer-judgments.json).
Содержательная разметка задаётся явно; офлайн-код проверяет её согласованность,
но не заменяет смысловую оценку нового произвольного ответа.

## Контракт и результаты системы

`input.source` содержит chunk, страницу и locator. Эталонная карточка следует
контракту `Card` из `docs/api/openapi.yaml`; evaluate использует
`EvaluateAnswerRequest` и метки текущего API. Формула и цитата проверяются дословно,
ответ — по смыслу. `abstain` — результат продуктового workflow без карточек,
а не добавленный статус внутреннего AI API. Перенос экзаменационного вопроса
в продуктовый адаптер не должен превращать вопрос в доказательный источник.

Записанные предсказания — JSONL по всем 40 ID. Например:

```json
{"id":"GD-021","task":"evaluate","status":"correct"}
{"id":"GD-017","task":"abstain","cards":[]}
{"id":"GD-001","task":"generate","error":"provider_timeout"}
```

Для успешной генерации передаются `cards` и `reviews` равной длины.
Review каждой карточки содержит boolean `grounded`, `useful`, `duplicate`,
`critical_error`, `covers_question` и непустое пояснение `evidence`.
Review заполняется по фактическому выводу системы; копирование эталона в predictions
не является измерением качества модели. Ошибки/таймауты остаются в знаменателе.

## Воспроизведение

```powershell
python -m pip install -r tools/quality/requirements.txt
python tools/quality/evaluate.py validate
python -m unittest discover -s tools/quality -p 'test_*.py' -v
```

Валидатор проверяет JSON Schema, checksum, все источники, страницы и цитаты,
19 ветвей UC, 20 оценок по рубрике и контрактные примеры.
PDF и извлечённые страницы сверяются по SHA-256. Формульные снимки и нормализованные
записи также фиксируются хешами. Изменение источника или оценки требует новой версии.

Детерминированная пересборка из сохранённого извлечённого текста:
`python tools/quality/prepare_example_dataset.py`.
Оригинальное извлечение: pypdf 6.21.4; визуальная проверка формул выполнена
по сохранённым изображениям. Обычная валидация не требует PDF-парсера, Docker,
API-ключей или обращения к модели.

После получения настоящих результатов системы:
`python tools/quality/evaluate.py score --predictions predictions.jsonl --output evaluation.json`.

Набор фиксируется версией и checksum. Новые кейсы добавляются с UC, страницей,
доказательством и рубрикой через PR; после изменения эталонов старые результаты
не перезаписываются. 40 кейсов из одной книги дают воспроизводимый регрессионный
контроль, но не доказывают статистическую устойчивость качества на всех дисциплинах.
