## Воспроизведение сейчас

```powershell
python -m pip install -r tools/quality/requirements.txt
python tools/quality/evaluate.py validate
```

Офлайн-проверка не требует `.env`, Docker или модели. Проверяет весь набор,
схему, уникальность, ссылки на контекст, цитаты, покрытие сценариев и контрактные
примеры. Отдельный workflow `.github/workflows/quality.yml` запускает её на PR.
Проверка также отклоняет потерю связи UC/ветвь/кейс, исчезновение исходного
раздела, несовпадение версии и повреждение Unicode. Регрессионные тесты:
`python -m unittest discover -s tools/quality -p 'test_*.py' -v`.

После реализации адаптер системы должен вывести predictions.jsonl согласно
README набора. Сам eval-инструмент не вызывает облако и не расходует токены:

```powershell
python tools/quality/evaluate.py score --predictions predictions.jsonl --output evaluation.json
```

Для генерации человек заполняет semantic review; без review автоматический PASS
невозможен. Таймауты и ошибки API адаптер сохраняет как `error`, а не пропускает ID.

## CI лабы 3

1. На каждом PR: текущая офлайн-валидация, unit/контрактные тесты и Compose smoke
   на чистой изолированной БД. Реальные интеграционные тесты добавить при реализации.
2. На изменении модели/промпта: полный frozen набор, не менее 3 прогонов с одинаковыми
   параметрами, каждый результат и разброс сохраняются отдельно.
3. Облачные evals — только вручную/защищённым workflow после разрешения владельца
   бюджета; секреты из CI secrets, запуск кода внешнего PR с секретами запрещён.
4. Приёмка человеком: UX, независимое ревью спорных эталонов и угрозы. Наличие
   YAML workflow не считается доказательством успешного GitHub CI.

## Метрики и правило решения

Для 16 generation кейсов Q1 = grounded / generated; Q2 = grounded и useful / generated;
Q4 = duplicate / generated; Q5 = covered cases / 16. Таймаут снижает Q5.
Abstain success = правильные отказы / 4, целевое значение 100%.
Q3 = exact status matches / 20, три класса; отдельно false-correct и бинарная
проекция correct против остальных (10/10). Во всех долях выводить числитель и знаменатель.
Пороговые значения — из `dod.md`, пока предложения до командного review.
Расхождение формы API и БД требует явного адаптера, а не скрытого переименования.

Задержка: фиксировать ≥ 20 запросов на фрагментах ровно 5000 символов,
температуру, модель, устройство/провайдер, concurrency, cold/warm режим;
p95 — элемент ceil(0.95*n) отсортированного ряда. Отдельно UI, оценка ответа и генерация.
Стоимость: токены входа/выхода, актуальный тариф, стоимость 10 принятых карточек;
нулевые результаты учитываются как потраченная стоимость. Тариф/порог сейчас не заданы.
Ранее предложенные 10 секунд на другом размере входа не использовать как gate.

## Условия остановки и отчёт

Stop: утечка данных/секретов, обход прав, исполнение модельного вывода,
критическая фактическая ошибка или ложное принятие опасного ответа.
Остальные дефекты: ID кейса, вход, ожидаемое/фактическое, severity, владелец,
SHA, версия набора/модели/промпта; исправление проверять регрессией.
В отчёте хранить хеш набора, параметры, объём, результаты, ограничения и ссылки.
Набор мал: не доказывает обобщение на другие конспекты,
удержание знаний, безопасность production и устойчивость точности в популяции.
