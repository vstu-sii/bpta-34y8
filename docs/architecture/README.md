# Лабораторная 2 — Delivery

Статус: проект для командного review. Основания: бриф, PRD, кандидаты моделей
и AI-контракт. Согласованных UC пока нет: сценарии ниже выведены из брифа.

| Сценарий | Данные | Ответственность |
|---|---|---|
| Конспект + вопросы → генерация | document, exam_question, generation_job | app → agent |
| Одобрение и источник | source_chunk, card | app + пользователь |
| Свободный ответ и самооценка | review, review_schedule | app, agent опционально |

## Архитектура

`c4-context.puml` описывает окружение, `c4-container.puml` — целевой MVP.
SQL-репозиторий — компонент API, не отдельный контейнер. Только app видит БД.
ADR в `../adr/` объясняют границы и цену решений. Выбор модели остаётся
в `../model-candidates.md`, а не в архитектурных ADR.

В лабе 2 API и AI являются заглушками. Диаграммы целевого MVP не означают,
что генерация, авторизация и повторение уже реализованы.

## Проверка

Из корня: `npm ci --ignore-scripts`, затем `npm run check:architecture`.
Рендер: `plantuml -tsvg docs/architecture/*.puml database/erd.puml`.
SVG лежат рядом с исходниками. C4 берётся из стандартной библиотеки PlantUML
внутри зафиксированного образа; загрузка include с ветки master не требуется.
Локально проверено контейнером
`plantuml/plantuml@sha256:9b5071ab56a4192aac458ab4b0d42261c22c8109695894ae5be6013c3be6cac1`.
Контейнер выполняет рендер локально; диаграммы не передаются веб-сервису.

## Согласование перед сдачей

- Product: сценарии, экраны и ADR (пока не согласованы).
- AI Engineer: локальный/облачный режим, контракт и лимиты AI.
- Quality: проверяемый DoD, угрозы и кейсы отказов.
- Схема и все четыре сервиса проверены в чистом изолированном Compose-проекте.
- Скриншоты и сценарий прототипа проверены автоматически в Edge; это не
  пользовательская приёмка UC.
- Health-заглушки не доказывают готовность MVP.

## Границы и адреса

`web` и `app` — сеть frontend; `app` и `db` — internal backend;
`app` и `agent` — сеть ai. Agent не подключён к сети БД, не получает credentials
и не публикует порт хоста. Его alias `ai-service:8000` совпадает с OpenAPI.
Исходящий доступ к согласованному провайдеру возможен через ai-сеть;
никаких запросов к модели в smoke-тесте нет.

Контракт: [API mapping](api-mapping.md). Проверки:
`python scripts/check-delivery.py`, `python scripts/check-compose.py`,
`npm run check:prototype`. Отчёт: [delivery-report.md](delivery-report.md).
