# ADR-001: единый владелец данных

Статус: предложено для review Product. Дата: 2026-10-17.

## Контекст

Четыре человека строят учебный MVP. Статусы карточек и расписание должны
быть согласованы; подтверждённой нагрузки для микросервисов нет.

## Решение и обоснование

API приложения — один Python-процесс, единственный клиент PostgreSQL.
Авторизация, планировщик, задания и SQL-репозиторий — компоненты этого процесса.
Frontend и AI-сервис запускаются отдельно, как показано в C4 Container.

В MVP длительная генерация создаёт persistent job. Один исполнитель внутри
приложения вызывает AI и сохраняет результат транзакционно. После рестарта
незавершённые задания повторяются без дубликатов. Брокер пока не нужен.
Альтернатива с отдельными CRUD-сервисом, worker и брокером увеличивает число
контрактов и отказов до появления реальной необходимости.

## Цена решения

API — единая точка отказа и масштабирования. Нужны ограничения очереди,
идемпотентность и восстановление заданий. Несколько реплик потребуют блокировок.
Общая схема БД связывает изменения компонентов. Правило aact crud отключено:
SQL-репозиторий не является отдельным процессом; его границы проверяются тестами.

## Как покрыть тестами

aact проверяет циклы и единственного клиента БД. В лабе 3: тест рестарта
генерации, отсутствие дубликатов, транзакции и изоляция данных владельцев.
