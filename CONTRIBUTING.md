# Правила работы с репозиторием

## Основная ветка

Основная ветка проекта — `main`.

Ветка `main` должна содержать стабильную версию проекта.

Прямые изменения в `main` не допускаются. Все изменения вносятся через отдельные рабочие ветки и Pull Request.

## Рабочие ветки

Для каждой задачи используется отдельная ветка.

Ветка создаётся на основе актуального состояния `main`.

Для лабораторных работ используется формат имени ветки, указанный в задании.


`lab[№]-[role]-initiation`

Например:

- `lab1-delivery-initiation`
- `lab1-ai-engineer-initiation`
- `lab1-quality-safety-initiation`

## Коммиты

Каждый коммит должен содержать логически завершённое изменение.

Сообщение коммита должно кратко описывать, что было сделано.

Примеры:

- `Add repository structure`
- `Update README`
- `Add pull request template`
- `Fix model loading`

## Pull Request

После завершения работы изменения отправляются через Pull Request в ветку `main`.

В Pull Request необходимо:

- кратко описать внесённые изменения;
- указать, как проверить результат;
- убедиться, что проект запускается;
- выполнить чек-лист из шаблона Pull Request.

Для работы в рамках текущего спринта каждый участник использует одну рабочую ветку и один Pull Request.

Все последующие изменения в рамках своей роли добавляются в эту же ветку и автоматически попадают в уже открытый Pull Request.

## Заголовок Pull Request

Заголовок Pull Request должен соответствовать формату, указанному в задании лабораторной работы.

Для лабораторной работы №1:

`Lab1: [Role] — Initiation Deliverables`


## После объединения изменений

После успешного объединения Pull Request рабочую ветку можно удалить.
